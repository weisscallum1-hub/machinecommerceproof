# Competitive Landscape — September 2026

## Broad category is not empty

The broad "agent identity/trust" category already has open standards and projects. Examples in the current ecosystem include:

- ERC-8004: identity, reputation and validation registries.
- EtereCitizen: identity/trust/commerce positioning using open standards.
- AgentPapers: public directory covering agent personhood infrastructure companies.
- AgentAudit and related research/projects: full-lifecycle agent trust/evidence and on-chain audit trails.

This means the defensible opportunity is **not** "another agent reputation protocol."

## Narrowed wedge

MCPx should focus on the operational transaction record:

**"Given an agent action, what was requested, what policy allowed it, what service executed, what was returned, what payment was associated, and can an independent verifier confirm the evidence?"**

That is a narrower product layer than identity registries or generic reputation scores.

## Why this wedge can coexist

- ERC-8004 explicitly leaves payment rails out of scope.
- x402 provides payments and discovery but is not itself an application-specific evidence/audit product.
- MCP exposes tools/resources but is not a payment reconciliation or evidence ledger.
- Agent directories aggregate information but are not execution receipts.

## Product positioning rule

Do not claim exclusivity. Win by being the easiest open implementation for paid agent actions and by accumulating high-quality, machine-verifiable evidence.

## Defensibility path

1. Open receipt schema.
2. Compatible adapters.
3. Public verifier.
4. Hosted historical evidence.
5. Payment-to-action reconciliation.
6. Reliability/reputation signals derived from evidence.
7. Integrations into agent marketplaces and developer tooling.
